# Cnab for .NET

[![CI](https://github.com/victorcondackdev/cnab-dotnet/actions/workflows/ci.yml/badge.svg)](https://github.com/victorcondackdev/cnab-dotnet/actions/workflows/ci.yml)
![.NET 8](https://img.shields.io/badge/.NET-8.0-512BD4)
![Dependencies](https://img.shields.io/badge/dependencies-0-brightgreen)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

A zero-dependency .NET library for FEBRABAN CNAB files, the fixed-width
formats Brazilian banks use to register boletos (*remessa*), report payments
back (*retorno*) and exchange payment instructions.

Layouts are declared as plain records with positions copied straight from the
bank manuals. The codec checks those declarations the first time they are
used, so a typo in a position fails a unit test instead of producing a file
the bank rejects three days later.

It is a port of the Go implementation,
[github.com/victorcondackdev/cnab-go](https://github.com/victorcondackdev/cnab-go),
and is **parity-tested against it**: the test suite contains vectors produced
by running the Go code, and the C# port must reproduce them exactly, from
decoded field values and error messages to the SHA-256 of every written file.

```csharp
public sealed record SegmentP : DetailSegment               // positions 1-13
{
    [CnabField(14, 1, CnabFormat.Const, Value = "P")] public string Segmento { get; set; } = "P";
    // ...
    [CnabField(38, 20, CnabFormat.Alfa)]  public string NossoNumero { get; set; } = "";
    [CnabField(78, 8, CnabFormat.Date)]   public DateOnly? Vencimento { get; set; }
    [CnabField(86, 15, CnabFormat.Money)] public long Valor { get; set; }  // cents
    // ...
}
```

## Why

- **Declarative layouts.** A record is a class; a bank is a set of classes.
  No hand-written `Substring` calls, no offset arithmetic spread across the codebase.
- **Layout self-validation.** Every position from 1 to the record length must
  be covered by exactly one field. Gaps, overlaps, out-of-range positions,
  format/type mismatches and integer properties too narrow for their width are
  reported together, by property name:

  ```
  fixedwidth: invalid layout Typo: overlap: Banco (1-3) and Lote (3-6); gap at 7-7 between Lote and Tipo
  ```
- **Compiled once, cached per type.** Reflection runs on first use; property
  accessors are bound to delegates and reused. The library is annotated for
  trimming and Native AOT (`IsTrimmable`, `IsAotCompatible`), and CI publishes a
  trimmed consumer that round-trips a real file.
- **Exact money.** Amounts are `long` cents end to end. No `double`, no
  `decimal` rounding, totals that add up.
- **Positional errors.** Every decoding problem carries the line, property,
  1-based positions and offending value, and a `CnabError` kind to switch on:

  ```
  cnab: line 3: field Valor (86-100) value "00000000000A000": must contain only digits
  ```
- **Lossless round trips.** Writing a parsed file reproduces the samples byte
  for byte; unknown segments are carried through untouched.
- **Reconciliation.** Match a retorno against the boletos you expect and get
  every difference explained: paid exact, paid with interest or discount, paid
  late, divergent, duplicate, unknown, rejected, still open.
- **Base class library only.** No dependencies, .NET 8 (LTS).

## Install

```sh
dotnet add package Cnab
```

The package is not on NuGet yet. Until then, reference the project or the
`.nupkg` produced by CI (the `nuget` artifact of the latest build).

## Quick start

### Build a remessa

```csharp
using Cnab;
using Cnab.Remessa;

var company = new Company
{
    Nome = "Acme Utilidades Ltda", Documento = "11.222.333/0001-81",
    Agencia = "01234", Conta = "000000056789", ContaDV = "0",
};
var bank = new Bank { Codigo = "341", Nome = "Banco Itaú S.A." };

var remessa = new RemessaBuilder(company, bank)
    .WithNsa(42)
    .AddBoleto(new Boleto
    {
        NossoNumero = "00000001",
        NumeroDocumento = "NF-1001",
        Vencimento = new DateOnly(2026, 12, 10),
        Valor = 150000,                       // R$ 1.500,00
        JurosPorDia = 50,
        Pagador = new Pagador
        {
            Nome = "João da Silva", Documento = "529.982.247-25",
            Endereco = "Rua das Laranjeiras, 1500", Bairro = "Laranjeiras",
            CEP = "22240-003", Cidade = "Rio de Janeiro", UF = "RJ",
        },
    });

using FileStream output = File.Create("remessa.rem");
remessa.WriteTo(output);   // throws RemessaException listing every invalid boleto, by index
```

The builder validates CPF/CNPJ check digits, CEP and amounts, folds accents
("João" becomes "JOAO") and truncates long names explicitly. Batch numbers,
record sequences and trailer counts are generated by `CnabWriter`; you never
maintain them by hand.

### Parse a retorno and reconcile

```csharp
using Cnab;
using Cnab.Cnab240;
using Cnab.Reconciliation;

using FileStream input = File.OpenRead("retorno.ret");
Cnab240File retorno = CnabFile.Parse(input);   // validates counts, sequences and structure

var expected = new[]
{
    new ExpectedBoleto { NossoNumero = "1", Valor = 150000, Vencimento = new DateOnly(2026, 12, 10) },
    // ... loaded from your database
};
ReconcileReport report = Reconciler.Reconcile(expected, Reconciler.EntriesFrom(retorno));
Console.Write(report.Summary());
```

values are matched after stripping spaces and leading zeros, since banks pad
the field differently in remessa and retorno. `new ReconcileOptions { GraceDays = n }`
tolerates payments on the next business day after a weekend due date.

### Work with records directly

```csharp
foreach (Ocorrencia o in retorno.Ocorrencias())          // T segment plus its U
{
    Console.WriteLine($"{o.T.NossoNumero} {o.T.Movimento.Label()} pago={o.U?.ValorPago}");
}

string line = FixedWidth.Serialize(segmentP, Layout240.LineLength);
SegmentP back = FixedWidth.Deserialize<SegmentP>(line);
Segment any = Segment.Decode(line);                       // P, Q, R, T, U or RawSegment
```

Errors derive from `CnabException`: `CnabFieldException` (property, positions,
value, line), `CnabLineException` (structural problems by line),
`CnabLayoutException` (every problem in a record declaration) and
`RemessaException` (every invalid builder input).

## Field formats

| Format             | Property type                                   | Encoding                                                                  |
|--------------------|-------------------------------------------------|---------------------------------------------------------------------------|
| `CnabFormat.Num`   | `string`, `byte`/`short`/`int`/`long`, enums     | digits, right-aligned, zero-padded; blank decodes as `""`/`0`             |
| `CnabFormat.Alfa`  | `string`                                        | left-aligned, space-padded, upper-case ASCII with accent folding          |
| `CnabFormat.Raw`   | `string`                                        | left-aligned, space-padded, verbatim (bank-reserved areas)                |
| `CnabFormat.Date`  | `DateOnly?`                                     | width 8 `DDMMYYYY`, width 6 `DDMMYY`; zeros or blanks are `null`          |
| `CnabFormat.Money` | integer types (cents)                           | digits with two implied decimals; negative values rejected                |
| `CnabFormat.Const` | `string`                                        | fixed literal (`Value = "P"`), verified on decode                         |

Positions are `start, length`, 1-based, exactly as printed in bank manuals.
Values that do not fit are errors, never silently truncated. Streams are read
and written as Latin-1, one byte per character, so any input round-trips; text
written to an alfa field is restricted to ASCII.

## Adding a bank layout

1. Write one record per record type, one property per row of the manual,
   including the filler rows ("Uso exclusivo FEBRABAN/CNAB"):

   ```csharp
   public sealed record DetalheRetorno
   {
       [CnabField(1, 1, CnabFormat.Const, Value = "1")] public string Registro { get; set; } = "1";
       // ... every position up to 394
       [CnabField(63, 8, CnabFormat.Num)]    public string NossoNumero { get; set; } = "";
       [CnabField(109, 2, CnabFormat.Num)]   public int Ocorrencia { get; set; }
       [CnabField(111, 6, CnabFormat.Date)]  public DateOnly? DataPagamento { get; set; }
       [CnabField(254, 13, CnabFormat.Money)] public long ValorPago { get; set; }
       // ...
       [CnabField(395, 6, CnabFormat.Num)]   public int Sequencial { get; set; }
   }
   ```
2. Add a test that pins the layout:

   ```csharp
   [Fact]
   public void LayoutIsComplete() => FixedWidth.Check<DetalheRetorno>(Layout400.LineLength);
   ```

   It throws a `CnabLayoutException` naming every gap, overlap and bad attribute.
3. Decode with `FixedWidth.Deserialize<DetalheRetorno>(line)`, or for CNAB 400
   files `CnabFile.Parse400` followed by `detail.Decode<DetalheRetorno>()`.

Shared prefixes are declared once in a base record (see `DetailSegment`, which
holds positions 1-13 of every CNAB 240 segment).
[`Cnab400/Bradesco`](src/Cnab/Cnab400/Bradesco/DetalheRemessa.cs) is a complete example.

## Supported layouts

| Layout | Records | Status |
|---|---|---|
| CNAB 240 cobrança (FEBRABAN generic) | file header 0, batch header 1, segments P, Q, R, T, U, batch trailer 5, file trailer 9 | Implemented from the FEBRABAN generic layout (v08.x-v10.x share these positions). Bank-reserved areas and code tables vary per bank. |
| CNAB 240, other segments (A, B, J, Y, S, ...) and record types 2/4 | | Preserved verbatim as `RawSegment`; not typed yet. |
| CNAB 240 pagamentos (SISPAG-style payment files) | | Roadmap. The codec supports them; the records are not written. |
| CNAB 400 cobrança, generic | header 0, detail, trailer 9 | Skeleton only: record type, sequence numbers and the common header fields. Details are decoded with a bank-specific record. |
| CNAB 400 Bradesco (237) remessa detail | type 1 | Experimental, from the public manual; not homologated. |
| CNAB 400 retorno layouts (any bank) | | Roadmap. |

Only movement codes whose meaning is identical across the FEBRABAN generic
layout are declared as enum values (`MovimentoRemessa.Entrada`,
`MovimentoRetorno.Liquidacao`, ...), each with a Portuguese `Describe()`.
Rejection reason codes (*motivos*) are returned as raw two-character codes
because their meaning is bank-specific.

## Cross-language parity

[`tools/vecgen`](tools/vecgen) is a Go program that links the Go
implementation and runs it over:

- the shared byte-exact samples in [`testdata`](testdata): full field dumps,
  written output (CRLF and LF), totals checks;
- 75 seeded random P/Q/R/T/U segments and 120 mutated segment lines;
- 200 mutated files (substituted characters, deleted, duplicated, swapped and
  truncated lines, line-ending variants), with the parse error or the SHA-256
  of the rewritten file;
- 49 remessa builder scenarios, valid and invalid, with the SHA-256 of the
  output or the full error text;
- 47 reconciliation scenarios, comparing `Summary()` and every result;
- every record layout (names, positions, formats), the codec on a reference
  record, accent folding and nosso número keys.

The output is [`GoVectors.g.cs`](tests/Cnab.Tests/Parity/GoVectors.g.cs);
[`ParityTests`](tests/Cnab.Tests/Parity/ParityTests.cs) asserts the C# results
are identical. Property names deliberately match the Go field names and the
FEBRABAN manual (`NSA`, `CNAB1`, `IOF`), which is what keeps error messages
identical across both implementations. To regenerate, with `cnab-go` cloned
next to this repository:

```sh
go -C tools/vecgen run . > tests/Cnab.Tests/Parity/GoVectors.g.cs
```

CI regenerates the vectors and fails if they drift.

Known representational differences: dates are `DateOnly?`, so a file date with
year 0000 (accepted by Go's `time` package) is rejected as invalid, and raw
fields count characters rather than UTF-8 bytes (identical for the Latin-1
content CNAB files carry).

## Testing

```sh
dotnet test
dotnet run -c Release --project benchmarks/Cnab.Benchmarks -- --filter '*'
```

Beyond the parity suite, the tests port the Go unit tests (every format and
error path, byte-level position checks of the samples taken directly from the
manual, independent of the attributes), and a seeded robustness suite feeds
thousands of mutated files, random segment lines and random builder inputs,
asserting that only `CnabException` is ever thrown and that writing is
idempotent. Sample files use fictitious companies, accounts and documents.

## Disclaimer

CNAB layouts are defined by FEBRABAN and, in practice, by each bank's own
manual, which may restrict codes, redefine reserved areas or deviate from the
generic layout. Always validate generated files against your bank's manual and
homologation environment before going to production. This project is not
affiliated with or endorsed by FEBRABAN or any bank.
